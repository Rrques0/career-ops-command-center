# Roadmap

## Phase 0 — foundation (current)

Audit the repository and Codex capabilities, establish durable project instructions, define the Study OS boundary, and obtain product review. No Study OS implementation.

## Phase 1 — specification

Choose the repository/app boundary, define the MVP learning loop, write domain terms and acceptance criteria, decide privacy/offline constraints, and record decisions.

## Phase 2 — architecture and tracer slice

Design the smallest end-to-end path from goal to planned session to completed session to reflection. Prove persistence, error behavior, and test seams with minimal infrastructure.

## Phase 3 — usable MVP

Add the approved session workflow, subject/goal management, basic history, and honest progress feedback. Keep AI, PDFs, sync, and advanced retention optional until the core loop earns them.

## Phase 4 — learning depth

Evaluate flashcards, spaced repetition, quizzes, weak-topic detection, and import/generation features against real use. Add only features with measurable learning value and clear provenance.

## Exit criteria for each phase

The phase has an approved scope, documented decisions, a small implementation plan, automated tests for changed logic, a manual verification path for user-visible behavior, and a review that names remaining uncertainty.
