# Design direction

## Status

This is a design brief, not an instruction to build the interface yet.

## Experience principles

- Make the next useful study action obvious without turning the home screen into a metric wall.
- Prefer truthful progress over decorative scores; label estimates, suggestions, and measured events separately.
- Let a learner move from plan to focus to reflection without losing context.
- Support keyboard and narrow screens from the first interaction design.
- Respect reduced motion and keep focus, empty, loading, offline, and error states intentional.

## Visual direction

Favor a focused workspace with clear hierarchy, generous reading space, restrained color, and one meaningful primary action. Avoid generic dashboard cards, excessive gradients, dense chart grids, gamification that obscures learning, and AI-generated content presented as authoritative.

## Hallmark decision

The Hallmark skill is not installed during foundation work. Its anti-pattern audit may be reconsidered when a Study OS interface exists, but it would add design instructions before there is a Study OS surface and could conflict with the existing root/Career Ops visual systems.

## Design verification

Future UI work must verify keyboard navigation, focus return, reduced motion, narrow-screen layout, honest empty/loading/error states, and the relationship between a recorded session and the progress shown afterward.
